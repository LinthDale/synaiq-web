# 實績展示擴充計畫

日期：2026-09-22。狀態：規劃稿，尚未修改網站功能或部署。

## 1. 目標與已確認方向

以「一個實績＝一個完整案例」整理內容。東京食品展的故事、現場照片、現場筆記與媒體報導全部歸在東京食品展內；之後每個新實績沿用同一內容架構。

使用者已確認：

- 東京食品展與現場筆記要整理在一起。
- 後續會持續增加其他實績，需要可擴充的結構。

以下的總覽、網址及資料設計是本計畫建議。新案例名稱、素材與實際成果仍由後續資料決定。

## 2. 現況與調整理由

依目前本機正式站來源 `live-prototype/` 核對：

- `cases-design.js` 是單一東京案例的固定版型，頁首也直接使用東京文案與照片。
- `locale-cases.js` 將故事、筆記、照片說明及報導放在同一組文字內，尚無案例清單。
- `prototype.js` 把 `#story`（東京食品展）與 `#fieldnotes`（現場筆記）列為兩個並列的頁內導覽項目。
- `locale-common.js` 的實績頁摘要只描述東京食品展。

因此，不能只在目前頁尾接上第二個案例；需要先區分「全部實績」與「單一案例內容」，讓訪客知道哪些內容屬於同一項實績。

## 3. 建議頁面結構

```text
實績展示總覽
├─ 頁首：實績展示的共同主題與簡介
├─ 案例列表
│  ├─ 東京食品展 → 東京食品展案例內容
│  └─ 後續新增案例 → 各自的案例內容
└─ 聯絡入口

東京食品展案例內容
├─ 案例名稱、摘要與主照片
├─ 基本資訊：日期／場域／應用內容
├─ 案例故事：背景需求、SynaiQ 的工作
├─ 現場紀錄：照片、圖說、現場筆記
├─ 媒體報導／來源
└─ 返回全部實績、聯絡入口
```

**總覽設計**

- 延續既有紙感、字體、留白與品牌配色。
- 頁首改為適用所有案例的介紹；「從台南到東京」等專屬文字移入東京案例。
- 每張案例卡包含封面、名稱、年月、場域／應用標籤、一句摘要及「閱讀案例」。
- 卡片採響應式排列；目前只有一筆時使用單張完整寬度的精選版面，多筆時排列成列表／網格。手機維持單欄。
- 首期只顯示有資料的案例，不為未提供的案例放空白卡片。預設依活動日期由新到舊，可設定一筆精選置頂。
- 「全部實績」是總覽；「現場紀錄」只在個別案例內出現。

**東京食品展整合**

- 保留目前已採用的故事、兩張現場照片、四語導覽資訊與兩則報導。
- 將三則現場筆記放在東京案例的「現場紀錄」區，與團隊合照一起閱讀。
- 目前 `01 / THE STORY`、`02 / IN THE FIELD` 改為案例內的小節標示，避免與案例排序混淆。
- 案例內可使用「案例故事／現場紀錄／相關報導」的小節導覽；全站主導覽仍只有「實績展示」一個入口。
- 卡片封面建議直接顯示照片，利於掃讀。東京詳情沿用現有照片／手繪配對；新案例沒有手繪時直接顯示照片，手繪不作為新增門檻。

## 4. 每個新案例需要的資料

| 資料 | 用途與規則 |
|---|---|
| 固定識別碼 | 例如 `tokyo-foodex-2026`；不因名稱或排序調整而改變 |
| 名稱與一句摘要 | 總覽卡片、案例頁標題；繁中與英文同步 |
| 日期、地點／場域 | 使用實際已知精度，只有年月就不補寫某一天 |
| 應用標籤 | 例如數位人、多語互動、知識服務；只標記該案實際提供內容 |
| 主照片與圖說 | 至少一張有使用依據的照片，包含中英文替代文字 |
| 背景與我們的工作 | 說明需求，以及 SynaiQ 實際負責的內容 |
| 現場紀錄 | 選填；照片、筆記、短片／外部影片連結等有資料才呈現 |
| 成果與來源 | 選填；數字需附來源，不將展會整體成果算成 AI 效益 |
| 媒體報導 | 選填；標題、媒體名稱、網址，各案例分別管理 |
| 公開狀態及排序 | 只公開內容完整且已確認可使用的案例 |

私人核對資料、原始簡報與未公開內容放在非公開工作資料中；不把它們放進公開 JS 後僅靠 `draft` 隱藏。公開資料模組只收錄可發布內容。

缺少筆記、報導或成果數字時省略該區塊，不顯示「待補」，也不要求所有案例湊成相同長度。舊站內容先核對；產品介紹或未確認參展的活動訊息不能直接轉成實績。

## 5. 實作與維護方式

以現有 `docs/design/live-prototype/` 擴充，維持靜態網站架構。

| 位置 | 預計工作 |
|---|---|
| `locale-cases.js` | 分成總覽文字與依固定識別碼管理的案例文字，繁中／英文使用相同識別碼 |
| 新增 `cases-data.js` | 管理已公開案例的日期、排序、照片、媒體網址；不放翻譯文字或私人證據 |
| `cases-design.js` | 共用的總覽與詳情版型，依案例資料渲染；不為每案複製一份 HTML |
| `prototype.js`、`i18n.js` | 解析案例網址，依總覽／詳情產生導覽，保留語言與案例參數 |
| `locale-common.js` | 實績總覽的共用導覽、標題與摘要改為多案例語意 |
| `site.css`、`tokens.css` | 增加案例卡片及詳情樣式；沿用既有視覺變數 |
| `page-metadata.js`、`sitemap.xml` | 為總覽與各公開案例提供對應中繼資料及中英文網址 |
| `assets/cases/<案例識別碼>/` | 新案例素材分資料夾；東京既有素材可保留原路徑 |
| `share-preview.mjs` | 將新模組、正式採用的素材加入公開白名單 |
| `preview.js`、維護文件及相關測試 | 預覽外框支援保留案例選擇，補上新增案例步驟與驗證 |

**建議網址契約**

- 總覽：`?page=cases&lang=zh-Hant`
- 東京案例：`?page=cases&case=tokyo-foodex-2026&lang=zh-Hant`
- 東京現場紀錄：同一案例網址加 `#fieldnotes`
- 舊連結 `?page=cases&lang=zh-Hant#story`／`#fieldnotes`：只在沒有 `case` 參數時，導向東京案例對應小節；使用替換歷史紀錄的方式避免上一頁循環。
- 無效或尚未公開的案例識別碼：顯示「找不到此案例」及返回總覽入口，設定不索引；不得默默顯示東京內容。
- 切換語言保留案例與小節；返回總覽保留語言；重新整理、直接開啟與瀏覽器上一頁都可使用。

目前 `pageHref()` 只保留 `page`、`lang`、錨點，而 `prototype.js` 會用它重寫頁內換頁連結。實作時須一起補上案例參數，避免新增卡片的 `case` 被重寫掉。

目前 canonical 與 sitemap 只分四頁、兩種語言。案例網址新增後須一起更新 title、description、canonical、hreflang、Open Graph 與 sitemap，避免不同案例全指回總覽。沿用現有客戶端中繼資料方式；外部分享平台是否讀取動態標籤另行實測，不將設定標籤等同於分享預覽已驗證。

完成後，新增一案的固定操作是：核對內容 → 增加雙語文字與一筆案例設定 → 放入照片並更新白名單 → 更新 sitemap → 預覽驗證 → 依發布流程上架。共用版型不需要跟著每案重寫。

## 6. 分階段執行

| 階段 | 工作 | 可檢查的產出 |
|---|---|---|
| A：整理東京案例 | 合併故事、照片、筆記及報導；區分總覽與案例內文 | 中英文內容清單、總覽與東京詳情的本機預覽 |
| B：建立擴充結構 | 完成共用版型、案例資料、網址、導覽與搜尋中繼資料 | 一個公開案例即可正常運作，舊連結仍可使用 |
| C：加入下一筆實績 | 取得名稱、日期、照片、工作內容及公開依據，套入既有版型 | 至少兩案可切換，新增案例不需改共用版型 |
| D：驗收與發布 | 完成雙語、手機／桌面及導覽驗收；需要上架時依操作文件發布 | 新版本直接網址及正式網址驗證、部署紀錄與回退資料 |

A、B 可先用現有東京資料進行，C 依新資料提供進度安排。這份計畫本身不執行 A–D 或切換正式站。

案例量增加後，再依使用情境擴充：有約 6–8 案且分類有意義時評估類型篩選；約 12 案以上評估年份或分頁；需要頻繁由多人編輯時再評估內容管理後台。這些數量是討論觸發點，不是首期必做功能。

## 7. 驗收標準

- 東京食品展是一個完整案例；現場筆記、照片與報導均位於其內。
- 總覽文案適用多個案例，只有一案與多案都沒有空白佔位或版面異常。
- 以僅用於測試的第二筆資料驗證擴充能力，不把虛構案例發布；新增資料不需修改共用版型。
- 每案識別碼唯一；雙語欄位一致；缺少選填區塊不出現空標題；照片與來源配對正確。
- 卡片、返回總覽、直接連結、語言切換、舊錨點及無效識別碼均符合網址契約。
- 總覽及各案例的雙語 title、description、canonical、hreflang、Open Graph、sitemap 對應正確；其他三頁沒有回歸。
- 390px 手機、835px 導覽斷點及 1440px 桌面實際檢視；鍵盤、圖片互動、reduced-motion 與錨點定位正常，沒有水平溢出。
- 執行 `npm run test:design`，更新案例／導覽／語言／SEO／白名單測試；搭配瀏覽器確認照片載入與頁面操作。共用素材或其他網站來源受影響時，依操作 README 增加對應檢查。
- 上架時依 [官網更新 README](../operations/WEBSITE-UPDATE-README.md) 使用新版本目錄，完成直接網址及正式網址驗證，並保留回退版本。
