## 1. 一句話定位與兩種訪客的任務

**定位**：SynaiQ 把企業與機關散落各處的文件，變成有憑有據、隨問隨答的知識中樞（SYNAIQ KIP）；
同一套知識可以在網頁、既有系統，或現場的 Wally 數位人身上回答問題。

| 訪客 | 他要做的事 | ≤ 2 次點擊的路徑 |
|---|---|---|
| 企業決策者（找 AI 導入夥伴） | 判斷 KIP 是什麼、能不能裝在自己機房、資安過不過關 | 首頁 → `/kip` →（第 2 擊）`/kip/security` 或 `/contact` |
| 政府／展覽客戶（找數位人與 Wally） | 看到型號、場域與**做過的實績**，然後預約展示 | 首頁 → `/wally` →（第 2 擊）`/cases` 或 `/contact` |

兩種訪客在首頁第一屏就必須看見自己的入口，且不需要下拉選單。

## 2. 資訊架構

### 2.1 KIP 如何成為主軸

`/knowledge-base` 現有文案（可查詢可追溯、答案附原文出處、查無依據明確告知、支援本地端部署）
與 KIP 簡報 `S1`／`S2` 高度重疊：**「企業知識庫」就是 KIP 的前身**。因此不新增第三個入口，
而是把 `/knowledge-base` 與 `/products` 一併收斂為 `/kip`，讓主軸只有一個名字。

| 現有路由 | 處置 | 理由 |
|---|---|---|
| `/products` 產品總覽 | **併入 `/kip`** | 只有 4 張導向卡，本身無內容；「總覽頁」會稀釋主軸，讓 KIP 看起來只是四分之一 |
| `/knowledge-base` | **併入 `/kip`** | 同一產品的兩個名字，文案幾乎可直接沿用 |
| `/agi` | **降級為 `/kip` 內的一段** | `S1` 顯示 AGI 那套能力（大模型層、知識智能體 IKA、MCP 介接）是 KIP 的一層，不是獨立產品 |
| `/wally` | **保留並列** | 硬體載具，買家、預算與決策流程都不同；定位為「KIP 的現場化身」 |
| `/generative-ai` | **保留但不進主導覽** | 內容產製（服飾試穿、商品情境影像）與知識問答是兩件事，簡報也未涵蓋；靠 footer 與內鏈進入 |
| `/media` | **併入 `/cases`** | 現況 5 處「待補」；新聞與活動放進實績頁才有上下文 |

## 4. 首頁敘事：六幕 GSAP 捲動的去留

**建議：移除**，改為 §3.1 的單一問答演示。（回答 PRD-003 OQ-2）

| 理由 | 說明 |
|---|---|
| 一個記憶點 | 六幕釘住式捲動等於六個記憶點，也就是沒有記憶點。設計準則要求把大膽用在一處，其餘克制 |
| 兩種訪客都在掃描 | 政府採購與企業 IT 都是來找規格與資安的，劫持捲動會直接拖慢他們，且無法用 Ctrl+F |
| 與已定架構衝突 | ADR-001 定調 Astro 零 JS 為預設、React island 只用在真互動處。釘住式捲動敘事是全站最大的一顆 island |
| 成本 | GSAP 加 ScrollTrigger 壓縮後約 50–70 KB，且必須整包在首屏載入才不會跳版；替換後的問答演示為內嵌資料、無網路請求，量級為個位數 KB |
| 可及性 | PRD-003 FR-306 要求 `prefers-reduced-motion` 降級。六幕敘事一旦降級就只剩六段沒有轉場的散裝內容，等於要維護兩套首頁 |

**保留的動態**：僅問答演示中「答案逐句出現、出處標記亮起」這一段，且它由使用者點擊觸發。
非使用者觸發的動態一律不做（不做逐段淡入上移、不做卡片 hover 位移）。

## 5. 聯絡方式：`mailto:` 還是真表單

**建議：改為真表單，同頁保留電話與 Email 明碼。**（回答 PRD-004 FR-406／OQ-5）

理由三點：使用 webmail、公務電腦未設預設郵件程式、或在展場用平板的訪客，點 `mailto:` 沒有
反應也不會回報，會直接漏單；表單能強制收齊「資料來源／使用對象／預期成果」，`mailto:` 只會
收到一行「請問報價」；公務單位傾向留下可追蹤的表單紀錄，而非私人信箱往返。

| 端點選項 | 說明 | 個資風險 |
|---|---|---|
| A 第三方表單服務 | Formspree／Web3Forms 等，純靜態可用 | 個資經第三方主機轉送，需簽委外處理並確認資料落地位置 |
| B Hostinger PHP 端點 | Hostinger 共享主機支援 PHP，可自建單檔收信端點 | 資料不經第三方，但 ADR-001 的「純靜態」需補一則 ADR |
| C 維持 `mailto:` | 零成本 | 無新增風險，但漏單問題不解 |

**個資與同意（三案皆適用）**：表單需以中文明列蒐集目的、保存期限、使用範圍與聯絡窗口，
同意勾選框**預設不勾選**且不得與送出按鈕綁定；不得蒐集非必要欄位；收件信箱與存取權限需指名；
選 A 時需在頁面揭露資料轉送給哪一家服務商。導入真表單時另開 ADR（PRD-004 FR-406 已要求）。

## 7. Fitroom showcase 觀察

**值得帶過來**

1. 整頁只有一個機制貫穿到底（捲動驅動模特旋轉），其餘元素全部讓位。這是「一個記憶點」的正確示範。
2. 主角是產品實體本身，不是插圖或抽象圖形；版面替實物留出大面積。
3. 版面刻意不對稱：內容欄靠一側約 42vw，影像佔另一側，沒有置中大標配三張卡的預設格。
4. 內文寬度控制在 30–36 字元，段落只有一到兩句，不用條列硬塞。
5. 標題字級以 `clamp()` 大幅跨距，行高壓到 1.0–1.04，且用**細字重**而非粗體取得份量。
6. 互動是可量測的：進度環加上「0°→360°」的即時讀數，讓捲動有狀態回饋，而不只是動畫。
7. 互動區只有兩個滑桿加一顆按鈕，結果立刻在旁邊換圖。一個高報酬的互動勝過十個小特效。
8. 等待狀態被當成內容經營：「不必乾盯，連結已存好，可以先去看別的」，把空窗期變成指示。
9. 同意勾選框用白話寫明用途與可刪除，且不預先勾選。
10. 雙語直接在同一段標記內並列 `.zh`／`.en`，兩語系版面同步演進，不會有一邊爛掉。
11. 幾乎沒有圓角（1px）與陰影，只有 hero 那張卡有一道深陰影：陰影用來指認主角，不當裝飾。

**不要帶過來（B2B／B2G 場景）**

1. 每個標題上方的全大寫寬字距眉標（SS26 · ATELIER、SEE IT TURN、FIND YOUR FIT、YOUR TURN，全頁五次），這是設計準則明列的通用套版特徵。
2. 捲動擦洗整頁影片背景：需逐格解碼、行動端 Safari 不穩、`prefers-reduced-motion` 無從降級，且會拖慢只想找資安規格的採購者。保留「一個機制」的紀律，換掉這個機制。
3. 近黑底加聚光加顆粒感的時尚編輯風：政府標案與企業簡報常需截圖轉貼或列印，這種處理會失真且顯得不莊重。
4. 氣氛先行的文案（「在黑暗中隨你的捲動緩緩轉身」）。保留第二人稱的直白，換掉抒情。
5. 文字按鈕尾綴 `→`、以中點串接的資訊列（「Powered by Fitroom · 白標虛擬試衣」），兩者都是準則點名的套版特徵。
