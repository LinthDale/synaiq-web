# KIP-D 官網改版計畫

日期：2026-10-30。狀態：使用者已確認重製首幀，本機已接入 V5 連續動畫。首頁、KIP 產品頁、三語文案與決策示例已實作，完整動畫及內容仍待使用者視覺驗收，未發布。依最新回饋，決策示例恢復原本產品對話介面，不能將回答章節改成另一套 UI。結尾導入入口文案仍待同步。

## 1. 改版目標與依據

產品定位改為「Synaiq KIP-D｜知識導向決策輔助」，英文全名依使用者註解為 Knowledge Intelligence Platform – Decision。延續 KIP 的知識整理、問答與來源追溯，新增對外敘事：整合依據、比較方案、說明建議與限制，協助人做出決策。

本計畫依據使用者提供的六則網頁標記、截圖，以及本機 `docs/design/live-prototype/` 現有實作。網頁讀取工具未能取得兩個外部網址內容，因此決策功能的判斷以使用者提供的產品截圖為準，未宣稱完成線上功能測試。

截圖已呈現：方案比較、預期淨效益排序、資金可行性、依目標不同給予建議，以及建議改變的條件。38.25／36／24 萬元是畫面中標示的預期淨效益，不應改稱投資金額、保證收益或客戶成效。完整輸入資料、計算公式與來源對應尚未取得，正式 demo 製作時須核對；不能由截圖補造。

暫採 KIP-D 為升級版對外名稱、KIP 為既有平台名稱；保留既有 `?page=kip` 路由，避免破壞外部連結。是否販售不同版本與授權方式不在本次提案中推定。

## 3. 貫穿首頁的滾動動畫

保留深色鉛筆素描、紙張、撕紙邊與少量暖金色的視覺語言。核心素材為文件碎片、知識線索、同一隻手、燈泡，以及方案分支。避免更換為不相干的科技粒子背景。

### 依自然頁面捲動展開的完整動作（依後續回饋修正）

以同一段連續鏡頭貫穿首屏、產品展示與 demo 深色背景。頁面正常往下捲動，首屏不固定，不要求看完動畫才能進入下一段；不增加純粹用來播放動畫的高度。

1. 打字機從紙滾輪吐出文件、字母與資訊，開場沒有大腦或燈泡。
2. 資訊沿一條跨越左右畫面的連續弧線流入手中，不能左右各自表演。
3. 收進手中的資訊逐步組成大腦，大腦的位置緊接手掌。
4. 手指完成一次打響指。
5. 同一個大腦在同一位置轉化為燈泡並亮起，保留與打字機相連的少量線索。

整段共用一個依背景可視範圍累計的捲動進度；不計入動畫被白紙／產業觀察遮住的距離。背景完全不可見時停格，僅少量露出時減慢，重新可見後接續原幀；停下即停格，往上即倒回。撕紙覆蓋範圍保守排除，視窗變更或內容展開後重算。此後續指示取代「首屏先完整播完再往下」及「整段頁面距離等比例播放」的早期設計。分鏡作為生成約束，不代表網頁切成數段影片。

### 各標記的延續方式

| 使用者標記 | 區域 | 動畫規劃 |
| --- | --- | --- |
| 1 | 首屏 `.home-opening` | 打字機開始輸出資訊；頁面隨正常捲動下移，動畫不強迫首屏停留。 |
| 3 | 敘事白紙下方的深色空間 | 同一組線索從撕紙後方露出，接續首屏進度；不留下突然中斷的純色帶。 |
| 2 | `.product-stage.product-reveal` 背景 | 線索分成 A／B／C 路徑，逐步靠近新版決策介面；前景產品與文字保持清楚。 |
| 4 | 產品區底部撕紙上側 | 燈光與路徑延續至撕紙邊界後方，與上下留白一起設計，避免截斷。 |
| 5 | `#proof` demo 區 | 同一條主線進入 demo，背景呈現方案分支與評估脈絡；結果出現時保留燈泡作結尾視覺。 |

白色紙張可遮住部分背景，但背景時間軸仍連續。深色區露出的是同一場景的後續狀態，不是各區各放一支影片。

產品區與 demo 之間保留「產業觀察」。依後續回饋，此不透明段落完整遮住動畫時停格，重新進入深色段落後接續；保留原出處與調查年份，不將產業數字改寫成 KIP-D 效果。

### 互動與實作原則

- 正常頁面滾動決定幀位置，停止滾動即停在該幀，向上滾動可回看；不攔截滾輪、不強制跳章。
- 首屏完整動作先以約一個視窗高度的捲動距離作為原型起點，依實際操作調整；不設定播放秒數，也不為湊幀數增加長篇空白捲動。其後讓動畫沿既有內容長度推進，避免整頁都被固定動畫拖長。
- 背景使用共用滾動進度與章節錨點；前景文字、按鈕、紙張遮罩及產品介面分層，背景不攔截點擊。
- 手部連續動作採同一構圖製作的幀序列；線條、光暈與路徑可用輕量向量圖層。先用少量關鍵幀檢查手勢，再補中間幀，不能把無關姿勢淡入淡出當成響指。
- 首輪先做可測試的幀序列原型，確認快速捲動、解碼負載與行動裝置記憶體，再定幀數、解析度與壓縮；不先承諾未驗證的播放效能。
- 素材分章預載，首屏文字與主要按鈕不等待全片下載。未載入時顯示相符的靜態畫面，避免黑屏。
- 手機以觸控捲動控制，另做手與燈泡完整可見的構圖。減少動態模式使用靜態關鍵畫面與完整文字。
- 改變視窗尺寸、切換語言、錨點跳轉與切離首頁時，須重算位置或清理動畫，避免錯幀與殘留背景。

## 4. 決策 demo 分鏡

主題採使用者現有的三方案比較。官網仍為示例動畫，與真實產品連線操作清楚區分。

| 段落 | 畫面與內容 | 要傳達的能力 |
| --- | --- | --- |
| 1 提問 | 「請比較三個投資方案的成本、預期效益與限制，建議先做哪一個，並說明理由。」 | 能理解需要取捨的問題。 |
| 2 整合依據 | 列出相關方案資料與限制，標示示例來源；缺少資料時直接顯示缺漏。 | 分析有輸入依據。 |
| 3 比較方案 | 逐列呈現 A 新設備、B 行銷開發、C 流程改善；欄位與單位依完整原始資料核對。 | 把分散資訊變成可比較的內容。 |
| 4 給出建議 | 依截圖標示的預期淨效益：A 38.25 萬元 ＞ C 36 萬元 ＞ B 24 萬元。 | 在明確指標下排序，而非無條件指定最好方案。 |
| 5 說明取捨 | 追求效益且可承擔較高投資時，可優先 A；重視較高達成機率與較小投資規模時，可考慮 C。 | 建議隨目標與限制不同而改變。 |
| 6 呈現重評條件 | 效益達成機率、初始投資、每年效益、資金上限與營運安全現金改變時，應重新評估。 | 結論有適用條件。 |
| 7 停留與核對 | 結果保留在畫面，可查看依據、往上捲動回看或使用章節入口；以燈泡完成視覺收尾。 | 決策者能理解並核對建議。 |

背景動畫維持「捲動距離 → 進度 → 對應幀」。依使用者最新澄清，前景產品 demo 必須像既有「知識問答」一樣自動展示多輪對話，不再用頁面捲動當作前景播放控制。七段內容節點收斂至三輪提問與回答。

決策 demo 的三輪對話為：「需要先整理哪些資料？ → 依現有分析比較三方案 → 目標不同時如何建議及何時重評」。每輪演示輸入、送出、等待與回覆；對話區保留前輪訊息，沿用既有側欄、提問氣泡、回答區、輸入欄與暫停／重播控制。章節入口可直接查看該輪回答並暫停；手動捲閱對話時暫停，減少動態模式呈現完整對話。背景仍依整頁黑色區域的自然捲動進度運作，依最新回饋，大腦至點亮燈泡增加約六成有效捲動距離，響指與變形核心段約兩倍，前後速度漸進銜接；既有知識問答與找圖示範保留。

不將「條件改變時應重評」表現成未經確認的即時試算器或自動執行決策。後續若產品已支援重新輸入條件並計算，可再加入實際追問的分鏡。

現有三段功能保留，新增決策輔助並設為預設第一段：決策輔助、知識問答、以自然語言找圖、以圖搜圖。首頁產品大圖同步改為決策比較畫面，避免主標已升級但圖片仍停在採購流程查詢。

Wally 保留為既有知識互動的現場入口；未確認設備上的決策模組整合前，不宣稱所有 Wally 型號都具備新增決策功能。

## 5. 建議製作順序與修改範圍

1. **內容與分鏡定稿**：先完成繁中文案、六則標記對照與七段決策分鏡；整理正式 demo 所需的完整問題、來源資料、單位、計算方式及產品回答。可先用明確標示的示例資料排版。
2. **動畫關鍵幀**：製作散落、連結、聚合、響指前、響指後、燈泡完成等關鍵畫面，核對手勢、風格與桌機／手機構圖，再補完整序列。
3. **貫穿動畫原型**：先打通首屏至 demo 的共用時間軸、撕紙遮罩與產品層次，測試可讀性及載入，再調精細動作。
4. **產品與 demo 升級**：新增決策比較介面與動畫分鏡，同步首頁示意圖、KIP 產品頁與三語內容。
5. **驗收與發布準備**：完成內容、視覺、操作、三語與效能驗證。正式發布依網站更新 README，另在使用者要求上架的範圍內執行。

現有實作：`home-design.js` 輸出首頁各區，`decision-scroll.js` 與 `decision-frames.js` 管理共用背景。`decision-demo.js` 產生決策回答，`demo-animation.js` 維持共用聊天外觀與四段示例切換；原有三段保留播放控制。

## 6. 驗收標準

- 六則標記均有對應：五處動畫區域完整覆蓋，第六則的比較、理由與重評條件均進入 demo。
- 首屏結尾可明確看出手指完成響指、燈泡出現並亮起，前後幀手部結構連續。
- 上下捲動能對應進度；停止捲動不持續播放背景；產品上下撕紙空隙沒有背景斷層。
- 新版主標、產品大圖、KIP 產品頁與 demo 使用相符的 KIP-D 定位，來源追溯能力仍被保留。
- Demo 數字、指標、單位、計算方式與建議條件一致；不把例子當成實績或承諾結果。
- 桌機、平板、手機檢查手與燈泡裁切、文字對比、點擊、捲動與橫向溢出；三語及減少動態模式可閱讀全部內容。
- 快速捲動、錨點進入、重新整理、語言切換、離開首頁及慢速載入時無黑屏與殘留圖層。
- 執行既有 `npm run test:design`，並針對新增的四段 demo、滾動幀與資源白名單補必要驗證；實際瀏覽器驗收不能由程式測試代替。

目前可在本機預覽檢查已實作的背景、文案與產品對話。技術檢查不等同使用者視覺接受；正式上架仍需使用者明確要求。
