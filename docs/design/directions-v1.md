## 方向一　文件與憑據（`direction-1-documents.dc.html`）

**世界觀**：知識的價值在於能被追回原件，所以整個網站長得像一份可稽核的文件。

**依據**
- KIP 唯一真正的差異點是 `S2`-6「每句都指得到／原文哪一份、哪一頁」與 `S2`-1「查不到就說查不到」。這是註腳的行為，不是卡片的行為。
- 企業與政府採購實際在做的是文件審查（十項資安、八項優勢），帳冊式的列表比插圖有用。
- 標誌的金色勾記直接對應「有憑有據」，可以當註腳記號用。

| 項目 | 內容 |
|---|---|
| 色票 | `#EDEFEF` 版心底（冷灰檔案紙）／`#FBFCFC` 文件面（對版心底 1.12，靠位置與陰影分辨）／`#1B2124` 正文墨（對版心底 **14.11**、對文件面 **15.84**）／`#5F6A6E` 邊註灰（**4.82**／**5.41**）／`#8A6A17` 出處金（對文件面 **4.92**；對版心底 4.38，故只用在文件面上的小字）／`#CCA858` 品牌金（對比 2.19，僅用於標誌與大面填色，不承載文字） |
| 字型 | 標題與內文：`Newsreader`（拉丁）＋`Noto Serif TC`（中文）。表格、邊註、按鈕、導覽：`IBM Plex Sans`＋`Noto Sans TC` |
| 配對理由 | Newsreader 是報紙閱讀襯線，字腔窄、經濟，同字級下與 Noto Serif TC 的宋體骨架灰度接近，中英混排不會一邊胖一邊瘦；IBM Plex Sans 的工程感方形骨架適合帳冊表格，且不與襯線爭主體。不用 Fraunces（設計準則點名的通用選擇） |
| 字級 | 12 / 14 / 17 / 21 / 28 / 36 / 46 px（0.75 / 0.875 / 1.0625 / 1.3125 / 1.75 / 2.25 / 2.875 rem）。正文 17px 行高 1.85（襯線加行距），行長 34 個中文字。行動版 H1 34px |
| 版面 | 1440 版心左右留白 80，主網格 `184px + 48px + 1fr`：左側是常駐的**邊註欄**，只放來源標註（「來源：KIP 簡報 S2」）與待補記號，不放裝飾。全頁左對齊，段落齊左不齊右 |
| 圓角線框陰影 | 圓角 2px 只給文件面（紙有裁邊），其餘為 0。分隔線只有水平橫線兩級：`rgba(27,33,36,.28)` 表頭與 `.14` 列間。**全頁只有一道陰影**，在首頁問答卡上，用來指認主角 |
| 動態 | 只有問答演示：點問題後答案逐句浮出、勾記亮起、出處列亮起。無捲動淡入、無卡片位移、無 hover 位移 |

**首頁記憶點**：Hero 右側的問答卡。三顆預設問題排成一疊，答案的每一句後面掛一個金色勾記加編號，下方是一張三欄帳冊
（記號／文件／頁次）。畫板上靜態呈現「第一句已核對」的狀態：勾記與第一列同時是實金色、第二句與第二列是半透明，並用一道
金色左線標出當前列。第三顆問題示範「查不到」，出處欄留空。

**從 Fitroom 帶來**：內文寬度 30 至 36 字、段落一到兩句；細字重取得份量（H1 是 200 字重）；近零圓角；陰影只給主角。
**拒絕**：全大寫寬字距眉標（既有 `.md` 裡的 `CORE CAPABILITIES` 一類全部拿掉）、中點串接的資訊列、按鈕尾綴 `→`、抒情文案。

**風險**：襯線中文在 Windows 舊機的 Noto Serif TC 回退字型可能較粗，需實測；帳冊列表若內容長度不均會顯得鬆散；
「文件感」對想看到科技感的展覽客戶可能偏保守。

## 方向二　現場的機器（`direction-2-machine.dc.html`）

**世界觀**：這台機器已經站在現場了，網站是它的規格書與現場紀錄。

**依據**
- 展位左牆已經定義了品牌的現場語彙：深底、電光藍線框模組、Wally 置中、LED 點陣眼。這不是新發明，是把既有語言帶上網。
- 展覽與政府客戶的第一個問題永遠是「多大、會不會動、放在哪」，答案是照片與規格，不是插圖。
- `wireframes-v1.md` §7 明列不要帶過來「近黑底加聚光加顆粒」，因為公文簡報常需截圖轉貼。

| 項目 | 內容 |
|---|---|
| 色票 | `#152430` 深底（均勻平塗石板藍）／`#1E3141` 面板／`#F1F5F7` 主文（對深底 **14.43**、對面板 **12.19**）／`#9FB6C4` 次文（**7.51**／**6.34**）／`#4FA8E4` 線框藍（**6.07**，來自展位左牆）／`#CCA858` 品牌金（**7.02**，只給 CTA 與標誌） |

| 字級 | 12 / 13 / 14 / 16 / 20 / 28 / 40 / 64 px（0.75 / 0.8125 / 0.875 / 1 / 1.25 / 1.75 / 2.5 / 4 rem）。正文 16px 行高 1.8，行長 34 字。行動版 H1 34px |

**從展位牆帶來**：深底＋電光藍線框模組、Wally 置中、LED 點陣眼。

**拒絕**：捲動擦洗影片背景、近黑底加聚光加顆粒、右牆的紫色光柱（紫色只出現在產品照片的螢幕內容裡，不進色票）、
全大寫眉標、`→` 尾綴。

**風險**：深底頁面列印時吃墨，需另備列印樣式；產品照片的紫色螢幕與藍色線框在同一屏會有兩個色相，需靠照片去背與尺寸控制；
若之後拿不到高品質現場照，整個方向會失去主角。

## 方向三　一套知識，兩個出口（`direction-3-two-exits.dc.html`）

**世界觀**：版面本身就是那張架構圖，左邊是知識、右邊是現場，中間一道金線是兩邊共用的知識底座。

**依據**
- 展位左牆的圖就是「Wally 置中、兩側接出模組」的分流圖，這個方向把它變成版面骨架而不是一張插圖。
- 兩種訪客（企業決策者、政府與展覽客戶）在首頁第一屏就要各自看見入口（`wireframes-v1.md` §1），分帶版面直接做到。
- `S1` 的四層架構裡，知識中心（KC）是核心，`S2`-5「多知識來源整合」說的就是同一套知識供多個出口取用。

| 項目 | 內容 |
|---|---|
| 色票 | `#DBDAD4` 知識帶／`#2E3238` 現場帶／`#191B1E` 墨（對知識帶 **12.32**、對紙面 `#F7F6F2` **15.96**）／`#EFEFEC` 亮字（對現場帶 **11.19**）／`#CCA858` 接縫金（對現場帶 **5.71**，對知識帶 1.61 故只做 4px 實體色塊）／`#8A6A17` 深金（對知識帶 **3.61** 可作圖形；出處記號一律放在紙面 `#F7F6F2` 上，**4.67**） |
| 字型 | 知識側：`Source Serif 4`＋`Noto Serif TC`。現場側：`Archivo`＋`Noto Sans TC` |
| 配對理由 | 兩個家族各是一組中英配對，指派本身承載資訊：看到襯線就知道自己在讀知識這一側，看到無襯線就知道在讀現場這一側。Source Serif 4 有光學尺寸軸、細字重穩定，與 Noto Serif TC 的宋體同為高對比結構；Archivo 與 Noto Sans TC 同為低對比黑體。兩組的 x 高度接近，跨接縫並排時基線不會打架 |
| 字級 | 知識側 12 / 14 / 17 / 21 / 29 / 40 / 50 px；現場側 12 / 13 / 15 / 18 / 24 / 32 px（現場帶較窄，字級整體降一階，強化「KIP 是主軸」）。行動版 H1 33px |
| 版面 | 每一列都是 `896px + 4px + 540px` 的三欄網格，中欄是不間斷的金色接縫；KIP 頁改為 `1096px + 4px + 340px`，右帶收窄成索引欄。知識側齊左，現場側齊左，兩側各自成欄。行動版接縫轉為橫向 4px 金線，兩側依序堆疊 |
| 圓角線框陰影 | 圓角 0，無陰影。容器語言分兩套：知識側是紙面色塊加水平橫線，現場側是 1px 亮邊框。接縫是唯一貫穿元素 |
| 動態 | 只有問答演示：問題壓在接縫上，點下去左右**同時**作答，兩側的出處編號一起亮起 |

**首頁記憶點**：橫跨接縫的問答條。問題寫在一條 720px 寬的紙帶上，紙帶左端是標誌的金色勾記，位置刻意壓過接縫伸進現場帶。
下方分出兩個答案：左邊是可核對的文件（襯線、出處帳冊、頁碼），右邊是 Wally 螢幕上的語音答案（無襯線、LED 點陣、同樣兩筆出處）。
兩邊引用同一批文件、同一個頁碼，這就是「一套知識」的字面意思。

**從展位牆帶來**：一個中樞接出兩側的結構。
**從 Fitroom 帶來**：不對稱、細字重大標、一個機制貫穿到底、近零圓角。
**拒絕**：近黑底、紫色、全大寫眉標、`→` 尾綴、等寬卡片牆。

**風險**：最高。分帶版面若內容量長期不均（現在 Wally 素材遠少於 KIP），右帶會變成長條空白；接縫在 4K 寬螢幕上要靠固定
`896px` 或百分比取捨；行動版把空間軸換成時間軸，訊息會弱掉一階；兩個字型家族等於四個檔案，載入預算要控管。
另外，這個方向的整個論述建立在「Wally 是 KIP 的現場化身」上，而這一點目前**沒有簡報依據**（`wireframes-v1.md` §8 第 2 項）。

## 比較

| 面向 | 方向一 文件與憑據 | 方向二 現場的機器 | 方向三 一套知識，兩個出口 |
|---|---|---|---|
| 可讀性 | 最高。全頁淺底、正文 14.11 對比、行長受控 | 高。深底但均勻平塗、正文 14.43 對比 | 高，但讀者要在兩套字型間切換 |
| B2G 截圖友善 | 最高。截圖與黑白列印都不失真 | 中。截圖清楚，列印吃墨，需另備列印樣式 | 中高。淺帶友善，暗帶列印吃墨 |
| 實作成本 | 低。純靜態、兩個家族、無特殊版面 | 中。軌道線與模組框需一套元件，照片需去背與最佳化 | 高。三欄接縫網格＋兩套字型系統＋行動版需另一套版面邏輯 |
| 與 KIP 主軸的貼合 | 最高。出處與註腳直接就是 `S2`-6 | 中。強在 Wally，KIP 靠線框模組表達 | 高，但前提是 Wally 與 KIP 的關係先定案 |
| 記憶度 | 中高。金色勾記＋帳冊是可辨識的資產 | 高。實機照片最直接 | 最高。接縫是別人抄不走的結構 |

### 建議：方向一，並把方向三的接縫概念留給 `/wally` 與 `/cases`

- **主軸決定形式**。已定案的主軸是 KIP，而 KIP 對外唯一站得住的差異是「答案指得到原文哪一份、哪一頁」。方向一把這件事
  做成版面的骨架（邊註欄、勾記、出處帳冊），不是做成一句標語。方向二把主角讓給 Wally，方向三則要先解掉品牌關係才成立。
- **素材現況支持它**。目前手上有的是文字（`S1`–`S6` 六張全文）與一張真實產品截圖；現場照片、案例照片、Wally 尺寸數據
  全部待補。淺底文件版面在素材不齊時仍然成立，深底照片版面不行。
- **風險最低而不無聊**。金色勾記來自標誌本身，是既有資產的重新使用，不是新發明的裝飾；業主否決過的深紫、淺紫、
  全大寫眉標、等寬卡片牆在這個方向裡一個都沒有。

若業主的優先順位是展覽現場與政府標案（而非企業 IT 導入），則改選方向二；方向三建議等 `待業主裁定` 第 1 項定案後，
再評估要不要整站採用。
