# 這套設計語言 v1（可施工版）

我把一套我很喜歡的網站語言拆開重寫成這份文件，用我自己的話講「我為什麼這樣做」。
所有數字都是量測值（電腦版 1440×900、行動版 390×844，逐段捲動實測），估算值會標「約」。
本文不描述任何特定站台，只描述這套語言本身。

---

## 0. 設計立場

我要訪客一進來就覺得「這是一個有主張的人做的東西，不是一份公司簡介」。
所以我把整站壓成兩種材質：一張紙，和一灘墨。內容站在紙上，主張站在墨裡，兩者交替出現，
用手繪的筆跡把它們縫在一起。

我拒絕三件事：拒絕滿版卡片格（三欄一列、每張一個圖示）、拒絕靠粗體與色塊喊音量、
拒絕把動態當裝飾。我要的音量來自**字級**與**留白**，不來自字重與顏色。
全站的彩色加起來不到畫面的百分之一，而且只出現在「人手畫上去的那一筆」。

## 1. 版面系統

### 1.1 容器與網格

| 項目 | 電腦版 1440 | 行動版 390 |
|---|---|---|
| 主容器 | `max-width: 1312px`，實際渲染 1280，左右各留 80 邊距 | 內容寬 342，左右各留 24 |
| 導覽高 | 74px（`4.625rem`） | 64px |
| 全幅段落 | 1440 滿版，內容仍收在 1280 內 | 390 滿版，內容收在 342 |

我不用欄位網格。我用的是**一組固定的量測欄寬**，每一種文字有它自己該有的寬度：

| 用途 | 寬 | 對應字級 | 每行約字數（英） |
|---|---|---|---|
| 首屏導語 | 420 | 24 | 30 |
| 立場段內文 | 500 | 28 | 36 |
| 行動呼籲標題 / 頁尾引言 | 640 | 64 / 40 | — |
| 深底段內文 | 700 | 18 | 75（偏寬，只因為它置中且只有 3 行） |
| 敘事大標 | 900 至 1100 | 60 至 84 | — |

**我的規則**：內文欄寬不超過 700，而且只有在「置中、三行以內」時才准用 700。
一般段落走 500。中文版把這兩個數字換成 **中文 24 至 30 字一行**，實作用 `ch` 或 `max-width` 都可以。

### 1.2 留白節奏

間距只用一組刻度（rem 換算 px）：2 / 4 / 8 / 12 / 16 / 24 / 32 / 40 / 56 / 64 / 80。
段落層級的內距我只用最後三檔：

| 段落 | 上下內距（電腦） | 上下內距（行動） |
|---|---|---|
| 首屏 | 80 | 80 |
| 數字段 | 200 | 60（中間斷點 92） |
| 頁尾 | 上 110、下 64 | 上 110、下 54 |

其餘段落不靠 padding 撐開，靠**段落自己的高度**撐開，見 §7 的高度級距。

### 1.3 一個畫面一個想法

這是整套語言最硬的一條。量測結果：全站八個段落，總文字量只有 1304 個字元，
最多的一段 393 字元，最少的一段 0 字元（純圖）。平均一段 163 字元。
換算成中文大約是**一段 60 到 110 字**。

所以每個段落只准有一句主張、一個媒介。要講第二件事就開新段落，不准在同一屏塞兩個標題。

### 1.4 首屏

首屏用 `min-height: 100svh`（不是 `100vh`，行動版瀏覽器工具列不會把內容切掉），
`overflow: hidden`，內容垂直置中、水平置中。電腦版量到 900 高、行動版 844 高。
裡面只有四樣東西：大標一行、導語兩行、一顆按鈕、以及散在背景的裝飾。
全首屏的可讀文字只有 93 個字元。

首屏底下**不放捲動提示箭頭**。下一段的頂緣會主動長進首屏的視野裡（見 §5.7），
那就是提示。

### 1.5 深底與紙白的切換邏輯

| 序 | 段落 | 底色 | 為什麼是這個底 |
|---|---|---|---|
| 1 | 開場 | `#292a2e` 深灰 | 進場先安靜，讓大標發亮 |
| 2 | 產品畫面 | `#292a2e` 漸層到 `#464669` | 承接開場，用藍紫尾把螢幕光帶出來 |
| 3 | 敘事 | `#e5e5e1` 到 `#f4f4f2` 到 `#f8f8f7` | 三階紙白由深到淺，越往下越亮，像翻頁 |
| 4 | 展示 | `#020203` 近黑 | 產品截圖要對比，只有黑底撐得住 |
| 5 | 立場 | `#f4f4f2` 紙白 | 講原則要回到紙上，不能演 |
| 6 | 數字 | `#f8f8f7` 次紙白 | 與上一段幾乎同色，用手繪波浪分界即可 |
| 7 | 行動呼籲 | `#1d1e20` 深墨 | 收尾拉回深色，與開場呼應 |
| 8 | 頁尾 | `#020203` 最深 | 全站最深的一塊，讓頁面明確結束 |

規律：**深、深、淺、深、淺、淺、深、深**。深色段落連續不超過兩段，淺色連續不超過三段。
導覽列在整條路上**維持紙白不變色**，它是唯一一個不隨底色改變的東西。

### 1.6 電腦與行動的差異

| 項目 | 電腦 | 行動 | 倍率 |
|---|---|---|---|
| 全頁高 | 7655 | 7309 | 0.95 |
| 首屏 | 900 | 844 | — |
| 產品畫面段 | 781 | 223 | 0.29 |
| 敘事段 | 1545 | 1895 | 1.23 |
| 立場段 | 1204 | 800 | 0.66 |
| 頁尾 | 705 | 1222 | 1.73 |

讀法：**圖變小、字變長、頁尾攤開**。行動版把左右兩欄改成單欄直排，
立場段電腦版的「大標左上、內文右下」對角構圖，在行動版一律改成左對齊直排。

## 2. 字型系統

### 2.1 四個角色

| 角色 | 特徵 | 用在哪 |
|---|---|---|
| 展示襯線（窄體、高對比、Didone 傾向） | 字重 **300**，字距 0 | 所有 40px 以上的標題、頁尾引言 |
| 內文無襯線（幾何人文混合） | 300 / 400 / 500 / 700 | 導語、內文、按鈕、導覽、頁尾連結 |
| 等寬 | 400 / 700 | 標籤、代號、資料型別（本語言備而少用） |
| 手寫 | 單一字重 | 手繪批註旁的小字（每頁至多兩處） |

關鍵是那個 **300 字重**。標題不靠粗，靠大。全站沒有一個 600 以上的標題。

### 2.2 字級階層（實測）

| 層級 | 電腦 px / 字重 / 行高 | 行動 px / 字重 | 備註 |
|---|---|---|---|
| 首屏大標 | 96 / 300 / 1.0 | 46.8 / 300 | 行動只有電腦的 0.49 倍 |
| 敘事大標 | 84 / 300 / 1.0 | 64 / 300 | 單行不斷字 |
| 段落大標 | 80 / 300 / 1.2（96px） | 40 / 300 / 1.2 | 深底與淺底共用 |
| 行動呼籲標 | 64 / 300 | 52 / 300 | |
| 次級敘事 | 60 / 300 | 40 / 300 | 用次要墨色 `#64645e` |
| 引言 | 40 / 300 | 32 / 300 | 頁尾 |
| 立場內文 | 28 / 400 / 1.5（42px） | 18 / 400 / 1.5（27px） | 唯一放大的內文 |
| 首屏導語 | 24 / 400 | 18 / 400 | |
| 出處署名 | 20 / 400 | 16 / 400 | |
| 一般內文 | 18 / 400 / 1.4（25.2px） | 16 / 400 | |
| 導覽與按鈕 | 16 / 400、按鈕 500 / 18px | 16 / 500 | |
| 小型大寫連結、批註小字 | 14 / 400 / `uppercase` | 14 / 400 | |

**字距一律 `normal`**。這套語言不靠 `letter-spacing` 做風格，包括全大寫的小連結也不加寬。
中文版必須例外：中文標題字距設 `-0.02em` 收緊，全大寫英文標籤設 `0.06em`。

標題可以多大？**電腦版上限 96，行動版上限 64**。超過就會在 390 寬度斷成四行，那時字級反而失效。

### 2.3 可授權的替代配對

原始展示字為付費字型，不得沿用。以下三組全為 SIL OFL 或 Google Fonts，可商用、可自架：

| 組 | 拉丁展示襯線 | 中文襯線 | 我的評語 |
|---|---|---|---|
| A | **Instrument Serif** 400 | **Noto Serif TC** 300 / 400 | 最接近原味：窄、高對比、有展示氣質。缺點是只有一個字重，階層必須完全靠字級拉開，這剛好符合 §2.1 的紀律。首選。 |
| B | **Bodoni Moda**（可變，`opsz` 96）400 | **Chiron Sung HK** Light / Regular | 對比最強、最有編輯感。40px 以下細筆會斷，所以只准用在 40px 以上，小字一律交給無襯線。 |
| C | **Newsreader**（可變，`opsz` 72）200 / 300 | **Noto Serif TC** 200 / 300 | 唯一真的做得出「300 字重的展示襯線」那種輕。窄度不足，需要 `letter-spacing: -0.01em` 補。最好讀，但最不搶眼。 |

內文無襯線建議 **Manrope**（OFL）配 **Noto Sans TC**；等寬建議 **Courier Prime**（OFL）；
手寫建議拉丁 **Caveat**（OFL）配中文 **芫荽 Iansui**（OFL）。
中文字檔很大，務必子集化，並對中文標題設 `font-display: swap` 加上一組系統襯線後備。

## 3. 色彩系統

### 3.1 角色與比例

| 角色 | 值 | 佔畫面 |
|---|---|---|
| 墨（主文字、主邊框） | `#282825` | 約 5% |
| 次墨 | `#64645e` | 約 2% |
| 弱墨（僅裝飾、絕不承載資訊） | `#8f8f89` | 約 1% |
| 紙 | `#f4f4f2` | 約 40% |
| 次紙 | `#f8f8f7` / `#ecece9` / `#e5e5e1` | 約 15% |
| 深墨面 | `#020203` / `#1d1e20` / `#292a2e` | 約 35% |
| 強調色 | 五色，見下 | **不到 1%** |

### 3.2 五個強調色與對比實測

| 名 | 紙上 | 對比（紙 `#f4f4f2`） | 墨上（深底用色） | 對比（深墨 `#020203`） |
|---|---|---|---|---|
| 藍 | `#2173be` | 4.48:1 | `#6ab8ff` | 9.79:1 |
| 綠 | `#529a6a` | 3.08:1 | `#56c87c` | 9.82:1 |
| 珊瑚 | `#eb5b55` | 3.10:1 | `#fe6862` | 7.28:1 |
| 紫 | `#c455eb` | 3.26:1 | `#dc78ff` | 8.07:1 |
| 橘 | `#f09236` | 2.15:1 | `#ffad5c` | 11.24:1 |

**這是本節最重要的一句**：紙上的五個強調色沒有一個通過 AA 內文標準（4.5:1）。
所以在紙上，強調色**只准當裝飾，不准單獨承載資訊**，而且只用在 40px 以上的大字或手繪筆跡。
深底上的反相色全部通過，可以放心用在小字。
墨對紙 13.42:1、白對深灰 14.34:1、紙白對最深墨 20.02:1，資訊層全部遠超標準。

### 3.3 強調色只出現在四個地方

1. 敘事大標中**唯一一個會換的詞**，每換一個詞換一個色。
2. 手繪批註的筆跡（底線、圈選、箭頭、波浪）。
3. 緊貼批註的 14px 小字說明，且必須與該筆跡同色。
4. 深底展示區的卡片填色（只用藍）。

導覽、按鈕、內文、表格、頁尾一律沒有顏色。這是為什麼那不到 1% 的彩色會有效。

### 4.1 手繪元素的用法

手繪只有三種身分，不可混用：

1. **場景線稿**：整段的主角，尺寸大到 320 至 700px，白線畫在墨上或黑線畫在紙上，
   放在段落的左下或右下角，允許被段落邊緣裁切。
2. **批註筆跡**：底線、橢圓圈選、彎箭頭、紅色波浪。永遠**貼著一段真實的文字**，
   位置用 `top: calc(100% - 0.25rem); left: 1.25rem; width: calc(100% - 2.5rem)` 這種相對定位，
   文字換行它就跟著換。一律 `pointer-events: none`。
3. **微粒**：小叉、星芒、火花。散布用，數量每屏不超過 8 個。

手繪元素**每個斷點手動重新擺位**（實測同一支箭頭在三個斷點分別是 160px 旋轉 90 度、224px 不旋轉、320px 靜態流排）。
不要指望它自動響應。

## 5. 動態系統

### 5.1 動態清單

| 名稱 | 觸發 | 時長 | 緩動 | 編排 | 距離 / 幅度 |
|---|---|---|---|---|---|
| 打字機大標 | 載入（DOM ready 後約 75ms） | 每字約 100ms，19 字約 1.93s | 線性（逐字，非緩動） | 只跑一次，不刪不重打 | 無位移 |
| 游標閃爍 | 打字結束後常駐 | 0.6s 一循環（另有 1s 版） | **硬切**，`0/49% 透明、50/99% 不透明` | 無限 | 無 |
| 換詞 | 進入視窗後常駐計時 | 每詞約 1000ms，5 詞一圈約 5s | 直接換，無淡入 | 循環 | 無位移，只換字與換色 |
| 進場揭露 | 進視窗（`IntersectionObserver`，`threshold: 0`，`rootMargin: 512px 0 0 0`） | 透明度 400ms、位移 500ms | 透明度線性；位移 `cubic-bezier(.19, 1, .22, 1)`（easeOutExpo） | 兄弟元素延遲 0.2 / 0.3 / 0.4 / 0.5s，即約 100ms 一階、最多 5 階 | 位移量小，約 16 至 24px |
| 批註筆跡繪出 | 進視窗 | 300ms | `ease-out` | 單一 | 由左至右擦出全長 |
| 線稿淡入 | 進視窗 | 600ms | 預設 | 單一 | 透明度 0 到 1，伴隨微幅 `scale` |
| 微粒閃爍 | 常駐 | 4 / 5 / 6s 各不同 | `ease` | 五條曲線相位錯開 | **只改 `opacity`** |
| 蒸氣與燈光 | 常駐 | 4s | `ease` | 三條錯開 | 只改 `opacity` |
| 星芒呼吸 | 常駐 | 3s 與 4s | `ease-in-out` | 無限來回 | `scale(.9) rotate(-1deg)` 到 `scale(1) rotate(1deg)` |
| 裝置說明輪替 | 常駐 | 6s 一圈，第 2、3 則延遲 2s | 預設 | 無限 | 只改 `opacity` |
| 按鈕 hover | hover | 300ms | 預設 | 無 | 只改顏色與陰影 |
| 導覽連結 hover | hover | 300ms | 預設 | 無 | 只改 `opacity` |
| 內文連結 hover | hover | 300ms | 預設 | 無 | 只改底線顏色 |

框架層另外量到的參數（供實作對齊）：`{ type: "tween", ease: "circOut", duration: 0.5 }`、
`staggerChildren` 0.1 / 0.15 / 0.2 / 0.4、`delayChildren: 0.1`、最常見 `duration: 0.3`。

### 5.2 打字機的節奏

我讓它在 DOM 就緒後 75ms 就開始，不等圖片。每字 100ms，一句 19 字打完 1.93 秒。
打完就停，游標留著硬切閃爍，**不刪除、不重打、不循環**。
理由：循環打字機會逼訪客等第二輪，一句話講不完的東西本來就不該放首屏。

### 5.3 換詞的節奏

一句大標裡只換一個詞，五個候選詞循環，每個停約 1 秒。每個詞配一個專屬強調色，
換詞同時換色。這是全站唯一一個「自己會動」的文字，也是強調色出場密度最高的地方。

### 5.4 手繪筆跡怎麼畫出來

不用 `stroke-dasharray`。實測作法是**遮罩擦除**：
把筆跡放成一張絕對定位的 SVG，加上
`mask-image: linear-gradient(90deg, black 0, black 33%, transparent 66%, transparent)`、
`mask-size: 300% 100%`，然後把 `mask-position` 從 `100% 0` 動到 `0 0`，
`transition: mask-position .3s ease-out`。
好處是任何形狀（含填色的、多段的）都能擦，不需要是單一路徑。

### 5.5 三個釘住場景的進度映射

| 場景 | 釘住方式 | 捲動行程 | 0% | 50% | 100% |
|---|---|---|---|---|---|
| 產品畫面 | `position: sticky; top: 74px; overflow: hidden` | 781px（等於它自己的高度） | 畫面完整釘在導覽下方，下一段的紙白邊緣剛從視窗底緣露出 | 紙白邊緣升到視窗中線，裝置下半被蓋住 | 紙白邊緣抵達導覽下緣，畫面完全被覆蓋，畫面本身**從頭到尾沒有動過** |
| 敘事大標 | `position: sticky; top: 74px`，高 600 放在高 1545 的容器裡 | 945px | 大標剛釘住，上方仍是前一段的紙白邊緣 | 大標持續釘著，兩層紙白波浪與線稿由下往上穿過它 | 容器走完，大標被推出視窗 |
| 數字段 | 宣告了 `sticky; top: 74px`，但容器高度等於它自己 | **0px（實際不會釘住）** | 與一般段落相同，隨捲動 1:1 移動 | 同左 | 同左 |

**我要說清楚第三個**：它寫了釘住卻沒有行程，量測結果是純線性捲動、數字不滾動。
這代表這套語言真正有效的釘住場景**只有兩個**，第三個是殘留的宣告。照抄時不要把它當設計。

第一個場景的機制值得單獨命名：**覆蓋式擦除**。被釘住的那一段完全不動，
是「下一段」升上來把它蓋掉。這比讓被釘住的元素自己縮放位移便宜得多，
而且行程長度直接等於段落高度，不需要算比例。

### 5.6 hover 狀態

全站 hover 只做三件事：改顏色、改陰影、改透明度。**沒有任何元素在 hover 時位移或縮放。**
時長一律 300ms。卡片不浮起、按鈕不長大、圖片不放大。

### 5.7 段落邊界

段落之間不是直線。作法是把一張 SVG 波浪放進**下一段**的頂部
（`position: absolute; top: 0; left: 0; right: 0`），再用 `transform: translateY(-50%)` 把它往上拉，
讓它蓋住前一段的下緣（另有 -60%、-64% 兩種變體）。
墨轉紙用粗糙的筆刷邊，紙轉紙用柔和的波浪邊。首屏底部就是靠這個把下一段「提前露出來」。

### 5.8 行動裝置與降級

原始語言在這裡是**有缺陷的**，我把它改掉：

| 項目 | 原樣 | 我的規定 |
|---|---|---|
| `prefers-reduced-motion` | 195KB 的 CSS 裡**一次都沒有出現** | 必須實作。開啟時：取消打字機（直接顯示完整句）、取消換詞（固定第一個詞）、取消所有無限循環、進場揭露改為 0.15s 純淡入、保留釘住但取消覆蓋動畫 |
| 流體字級 | 沒有用 `clamp()`，改用 40 個斷點硬切 | 標題一律 `clamp()`，斷點收斂到 640 / 1024 / 1440 三個 |
| 釘住場景 | 電腦 2 個有效 | 行動版**全部關閉**，改成一般順序段落。行動的產品畫面段從 781 壓到 223（0.29 倍），沒有空間釘住 |
| 手繪微粒 | 各斷點手動擺位 | 行動版數量減半，且只保留不與文字重疊的 |

### 5.9 效能預算

1. 動畫只准改 `transform`、`opacity`、`mask-position`。實測所有循環動畫都只改 `opacity`，這是對的，照做。
2. **全站釘住場景上限 2 個**，單頁上限 1 個。
3. 無限循環動畫每屏上限 5 條，且相位必須錯開（實測是 4s / 5s / 6s 三種週期交錯）。
4. 不要為了這套語言載入三套動畫函式庫。原始站的共用套件同時打包了捲動觸發引擎、
   React 動畫函式庫、兩套輪播，光那一個共用檔就 145KB。
   本語言真正需要的只有：`IntersectionObserver`（原生）加 CSS `transition` 加 CSS `@keyframes`。
   兩個釘住場景用純 `position: sticky` 就能做到，**不需要任何函式庫**。

## 6. 文案聲音

| 位置 | 字數預算（中文） | 句式 |
|---|---|---|
| 首屏大標 | 8 至 14 字，一行 | 直述句，句號結尾。不用問句、不用標語體 |
| 首屏導語 | 兩行，共 30 至 40 字 | 一句話講清楚「這是什麼」，不講好處 |
| 段落大標 | 10 至 20 字，最多兩行 | 可以有轉折（前半鋪陳、後半否定），轉折那半用斜體或換色 |
| 段落內文 | 60 至 110 字 | 兩到三句，每句一個意思 |
| 批註小字 | 6 至 12 字 | 像人在旁邊補一句話 |
| 按鈕 | 2 至 6 字 | 動詞開頭 |
| 頁尾連結 | 2 至 6 字，全大寫 | 名詞 |

標題與說明的關係：**標題講主張，說明講依據**。說明不准重複標題已經說過的詞。

禁止事項：不用驚嘆號；不用「業界領先」「全方位」這類形容；
不用「＋」「→」「·」串接資訊；每頁全大寫寬字距眉標最多兩次；
不寫氣氛文案（描述訪客感受的句子一律刪掉）。

## 7. 頁面編排原型

| 序 | 段落 | 電腦高度級距 | 行動高度級距 | 媒介 | 底 |

| 3 | 敘事 | 1500 至 1600（含 600 的釘住區） | 1800 至 1900 | 大字 + 線稿 | 紙（三階漸亮） |
| 4 | 展示 | 1100 至 1200 | 1200 至 1300 | 截圖輪播 | 近黑 |

## 8. 轉譯成 KIP

| 原元素 | KIP 版本 | 理由 | 所需素材 / 待補 |
|---|---|---|---|
| 手繪的指標與人形 | **手繪風格的「人在查資料的樣子」**：一個人俯身在成堆卷宗前翻找，線稿 | 這是 KIP 要解決的問題本身，比任何圖示都準確 | 需委製線稿 1 張（首屏）**待補** |
| 打字機大標 | **KIP 逐字寫出一個問題的答案** | 用產品的行為當標題，不用標語 | 決定那一句答案的文案**待補** |
| 漂浮的字母 | **文件碎片與引註標記**：頁碼、章節號、附檔名、段落編號 | 字母對寫作站成立，對知識庫不成立；碎片才是我們的原料 | SVG 一張，弱墨 `#8f8f89` |
| 裝置場景（釘住） | **KIP 介面截圖 + 現場的 Wally** | 一屏同時回答「軟體長怎樣」與「現場長怎樣」 | 介面截圖 3 張（去識別）、Wally 現場照 1 張**待補** |
| 立場段（原則主張） | **資料主權與地端部署** | 這是對政府與企業採購最有力的一句，而且是既有簡報已寫的內容 | 沿用簡報既有段落，需業主確認可對外承諾 |
| 計數器 | **部署數字**（案場數 / 文件數 / 單位數） | 一個數字比三個數字有力 | 數字**待補**；在數字到位前，此段改為單一實績句 |
| 會換色的那個詞 | **輪替的文件型態**：PDF、掃描件、手寫、試算表、圖片，各配一個強調色 | 一句話證明「什麼格式都吃得下」，是 KIP 最容易被懷疑的一點 | 五個詞與配色定案 |
| 紅色波浪底線 | **「查不到就說查不到」的標記**：沒有出處的句子畫紅波浪 | 把拼字檢查的視覺直覺，轉成幻覺防護的視覺直覺 | 需一組示範問答 |
| 手繪圈選與箭頭批註 | **出處標記**：把有依據的那句圈起來，旁邊 14px 小字寫「來源：某文件 第 12 頁」 | KIP 唯一真正的差異點就是可追溯，這是它的視覺化 | 示範用的假文件名稱（不得用真實客戶文件） |
| 深底截圖輪播 | **三張 KIP 介面**：智慧搜尋、知識中心後台、分庫權限 | 用真畫面取代功能卡牆 | 截圖 3 張、去識別處理**待補** |
| 頁尾引言 | **一句關於「知識留在組織內部」的引言** | 收尾要留一個立場，不要只留連結 | 引言來源與授權**待補**；查不到就整塊拿掉，不編造 |
| 綠色與紅色小批註 | **兩句承諾**：一句資料主權、一句資安 | 用最小的字放最重的承諾，比大標更可信 | 兩句文案需業主核可（屬對外承諾） |
